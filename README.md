# MASQUERADE ― 仮面領の一夜

正体を隠したまま王位継承の駆け引きが行われる「仮面領」の、一夜限りの舞踏会を舞台にしたオリジナルの心理戦カードゲームです。

- 舞台：正体を隠したまま王位継承の駆け引きが行われる「仮面領」の一夜限りの舞踏会
- 手札＝「今夜だけ被っている仮面」というメタファー
- 脱落＝「正体を見破られ、舞踏会から退場させられる」

> **設計方針について**：いわゆる「ラブレター系」（手札1枚・ドロー＆ディスカードで効果発動・心理戦）と呼ばれるジャンルの**仕組み**を土台にしていますが、キャラクター・世界観・カード効果の組み合わせ・カード名・ゲーム名はすべて独自に設計しています。既存の商業カードゲーム（XENO等）と偶然名称や効果が似てしまった箇所は、判明ししだい独自の内容に変更しています（詳しくは更新履歴を参照）。

## 遊び方

- 基本の手札は**1枚**。自分の番には山札から1枚引いて**一時的に2枚**になり、そのうち1枚を場に出します。出した仮面の効果が発動し、時には相手を脱落させることもできます。
- **最後まで残った人**、または**山札が尽きた時点で一番大きい数字の仮面を持っていた人**の勝ちです。
- 自分と対戦相手は、それぞれ独立した山札（構成は同じ・並びは別々にシャッフル）を持っています。ゲーム開始時に、両者の山札からそれぞれ1枚が「封印の仮面」として裏向きに除外されます。
- カードの効果が発動するのは、**自分の番に自分でその仮面を場に出した時だけ**です。他人の効果で捨てさせられた場合や、山札切れによる最後の公開では、効果は発動しません（例外：「仮面の主催者」の自分自身の脱落だけは、捨てさせられた場合にも発動します）。

## カード一覧（全10種）

| 数字 | 名前（読み） | 効果名 | 枚数 | 効果 |
|---|---|---|---|---|
| 1 | 給仕（きゅうじ） | 看破 | ×2 | 相手の手札の数字を宣言する。的中すれば相手は即座に脱落する。 |
| 2 | 楽団員（がくだんいん） | 探知 | ×2 | 対象の手札が「6以上」か「5以下」かだけを知る（正確な数字は分からない）。 |
| 3 | 預言者（よげんしゃ） | 暴露 | ×2 | 対象の手札を選び、その正体をその場にいる全員に公開させる。 |
| 4 | 貴婦人（きふじん） | 加護 | ×2 | 次の自分の番が来るまで、他人の効果を受けない。 |
| 5 | 密偵（みってい） | 隠密 | ×2 | 自分の山札の一番上をこっそり確認し、そのまま戻すか山札の底へ送るか選べる。 |
| 6 | 道化師（どうけし） | 悪戯 | ×2 | 自分と対象、双方の仮面を公開で捨てさせ、新しい仮面に総入れ替えする。 |
| 7 | 毒見役（どくみやく） | 毒杯 | ×2 | 対象の仮面を、誰にも見せぬまま密かに処分し、山札から新しい1枚を引かせる。 |
| 8 | 黒騎士（くろきし） | 決闘 | ×2 | 対象と手札の数字をこっそり比べ合い、低い方が脱落する（同数なら何も起きない）。 |
| 9 | 大公（たいこう） | 封印 | ×1 | 対象の次の番を封じる。次の番、対象は仮面を引くことも場に出すこともできない。 |
| 10 | 仮面の主催者（かめんのしゅさいしゃ） | 共倒れ | ×1 | 自ら場に出すと自分は即座に脱落するが、その瞬間、対象も道連れにして退場させる（貴婦人の加護があれば対象は免れる）。他者の効果で捨てさせられた場合は、自分だけが静かに脱落する。 |

いずれの効果も「貴婦人の加護」で無効化できます。効果が無効化された場合、行動した側・守られた側の両方の画面に、その旨を知らせる表示が出ます。

## 対戦形式

### CPU対戦

3段階の難易度があります。

| 難易度 | 特徴 |
|---|---|
| 新米仮面卿 | 駆け引きに不慣れで、隙が多い |
| 仮面卿（標準） | 標準的な駆け引きをこなす |
| 老獪な仮面卿 | 捨て札からの数字推測・防御的なカード温存など、高度な読みで挑んでくる |

CPU戦の対戦成績（勝敗数・連勝記録）は難易度ごとに端末内へ保存されます。ホーム画面の戦績表示から、現在選んでいる相手との記録をリセットすることもできます。

### オンライン対戦

合言葉（5文字のコード）を使って、離れた相手と1対1で対戦できます。部屋を作って合言葉を相手に伝えるか、相手から受け取った合言葉で部屋に参加します。**利用にはご自身のFirebaseプロジェクトの設定が必要です**（次項参照）。

- 対局中、あらかじめ用意した8種類の定型文で簡単な会話ができます（自由入力ではありません）
- 対戦相手との接続が25秒以上途絶えると警告が表示され、いつでも対局を終了できます
- 相手がリタイア、またはホーム画面へ戻った場合、両者の画面で対局が正しく終了します
- 決着後、同じ部屋・同じ相手のまま再戦できます
- 対局の結果はランキング（後述）に記録されます

## オンライン対戦のセットアップ（Firebase）

**オンライン対戦を使うには、あなた自身のFirebaseプロジェクトが必要です。** 以下の手順で準備してください。

1. [Firebase コンソール](https://console.firebase.google.com/) で新しいプロジェクトを作成する
2. 左メニューの「Authentication」→「Sign-in method」から、**匿名（Anonymous）** を有効にする
3. 左メニューの「Firestore Database」から、データベースを作成する（本番モードでもテストモードでも構いません。セキュリティルールは手順5で設定します）
4. 「プロジェクトの設定」（歯車アイコン）→「全般」タブの一番下、「マイアプリ」でウェブアプリを追加し、表示される `firebaseConfig` の値をコピーする
5. `mask-game.js` 内の `firebaseConfig`（ファイル冒頭から検索すると見つかります）を、コピーした値で書き換える：
   ```js
   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "...",
   };
   ```
6. Firestore の「ルール」タブを開き、以下のセキュリティルールを貼り付けて公開する（**最新版です。以前のバージョンから変更されている場合は、必ず貼り付け直してください**）：
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /rooms/{roomId} {
         allow read: if request.auth != null;
         allow create: if request.auth != null;
         allow update: if request.auth != null && (
           resource.data.hostUid == request.auth.uid ||
           resource.data.guestUid == request.auth.uid ||
           (resource.data.status == 'waiting' && resource.data.guestUid == null
             && request.resource.data.guestUid == request.auth.uid)
         );
       }
       match /leaderboard/{uid} {
         allow read: if request.auth != null;
         allow write: if request.auth != null && request.auth.uid == uid;
       }
       match /_diagnostics/{docId} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
   - `rooms`：対局の部屋。3つ目の条件により、「まだ誰も参加していない部屋」に対して、自分のuidを`guestUid`として書き込もうとしている場合（＝参加しようとしている瞬間）だけ、参加者による最初の書き込みを許可します。
   - `leaderboard`：ランキング。全員が読めますが、自分の記録（自分のuidの文書）にしか書き込めません。
   - `_diagnostics`：「接続テスト」機能が一時的にデータを書き込んで読み書きを確認するための、テスト専用の置き場です。

### 「データベースが作成できているか」ご自身で確認する方法

Firebaseコンソールの「Firestore Database」を開いた際、画面中央に大きく「データベースの作成」というボタンが出ている間は、上記の手順3がまだ完了していない状態です。既に作成済みの場合は「データ」タブが表示されます（対局が一度も行われていなければ空の状態です）。

### うまく繋がらない時は

うまくいかない場合は、その場に表示されるエラーメッセージの内容をご確認ください。特に `permission-denied` の場合はセキュリティルールの見直しを、タイムアウトの場合はFirestoreデータベースの作成状況をご確認ください。

## その他の機能

- **BGM**：画面右上の🎵ボタンでオン/オフを切り替えられます（初期状態はOFF。ブラウザの自動再生制限のため、最初の画面タップ時に再生を試みます）。「仮面の円舞曲」（約3分35秒）をループ再生します。アプリを開いている（タブが表示されている）間だけ再生され、他のアプリに切り替えたりタブを非表示にすると自動的に一時停止します。
- **効果音**：画面右上の🔊ボタンでオン/オフを切り替えられます。
- **カード効果ごとの専用演出**：10種すべての効果に、それぞれ異なる一瞬の演出（発動時の光・アイコン・呼び名）が入ります。`prefers-reduced-motion`（アニメーションを控えたい設定）が有効な環境では省略されます。
- **ランキング**：オンライン対戦の結果をもとにした、ユーザー同士のランキングです。勝利+3pt／引き分け+1pt／敗北+0pt。表示名（12文字まで）を設定でき、ランキング画面から上位30名を確認できます。CPU対戦の戦績とは別に記録されます。
- **チュートリアル**：ホーム画面下部「はじめての方はこちら」から、10種類のカード効果を1枚ずつ紹介する一覧と、実際の練習対局（CPU・新米レベル）で基本的な遊び方を学べます。
- **開始・再戦の確認**：「舞踏会をはじめる」「もう一度舞踏会へ」を押した際、確認のワンクッションが入ります。

## 開発・デプロイ方法

### GitHub Pagesへのデプロイ手順

1. GitHubにこのフォルダ一式をpush
2. リポジトリの Settings → Pages を開く
3. Source を「Deploy from a branch」、Branch を `main`（またはpush先のブランチ）／ `/ (root)` に設定して保存
4. 数十秒〜1分待つと `https://ユーザー名.github.io/リポジトリ名/` で公開される
5. スマホでそのURLをブラウザで開き、共有メニューなどから「ホーム画面に追加」

### 更新すると、スマホのアプリは自動で更新されますか？

**要点：** 削除・入れ直しは不要ですが、**アプリを開き直すことが更新のトリガー**になります（ネイティブアプリのようにバックグラウンドで自動更新されるわけではなく、これはPWA全般の仕組み上の制約です）。

1. GitHubにpush → ホスティング側がビルド・デプロイ（数十秒〜1分程度）
2. スマホでアプリを開く → Service Workerが起動時に最新の `index.html` / `mask-game.js` をネットワークから取得
3. 取得できれば即座に最新版を表示。取得できなければ（オフライン時など）直近のキャッシュ版を表示
4. アプリを開いたまま裏で待機していた場合は、新しいバージョンを検知した時点でそのタブが自動的に1回だけリロードされます

**ファイルを更新するたびに、`sw.js` 内の `CACHE_NAME` は必ず1つ上げてください**（同じ名前のままだと、静的資産のキャッシュが更新されないことがあります）。

## 動作確認・テスト方法

```bash
node smoketest.js
```

CPU同士を指定回数（既定40戦）自動対戦させ、クラッシュや異常終了がないかを確認します。カードの効果やゲーム進行に変更を加えた際は、このテストが通ることを確認してから反映しています。

## 設計上の制約について（正直な開示）

- **オンライン対戦の秘匿性について**：対戦相手の手札を本当の意味で秘匿する（サーバー側だけが両者の手札を見られる仕組みにする）には、Cloud Functions等の有料プランの仕組みが必要になります。現在はクライアントのみで完結する構成（Firestoreの無料枠内で動く構成）を優先しており、「部屋の参加者2人だけが読み書きできる」というセキュリティルールで保護しつつ、画面上は相手の手札を表示しないという設計にしています。技術的に踏み込んだ人がブラウザの開発者ツールでネットワーク通信を覗けば、理論上は相手の手札を先に知ることも可能です。友人とカジュアルに遊ぶ用途を想定した割り切りです。
- **この開発環境からの制約**：この環境からは実際のFirebaseサーバーへ接続できないため、オンライン対戦・ランキング機能について、コード上の動作確認（自動テスト・ロジック検証）はできますが、実機・実際の複数端末でのテストはできません。不具合が見つかった場合は、実際のエラーメッセージや状況を教えていただくことで、より正確に対応できます。
