# MASCARADE ― 仮面領の一夜

正体を隠したまま王位継承の駆け引きが行われる「仮面領」の一夜限りの舞踏会を舞台にしたオリジナルの心理戦カードゲームです。XENO（中田敦彦氏考案、ラブレターがベースの商業カードゲーム）から「手札1枚・ドロー＆ディスカードで効果発動・心理戦」という**仕組み**だけを参考にし、キャラクター・世界観・カード効果の組み合わせ・ゲーム名はすべて独自に設計しています。

> **開発の経緯**：本ゲームは開発初期には別の名前で呼ばれていましたが、現在は **MASCARADE** に改名しています。以下の更新履歴もすべて新名称に統一しています。

- 舞台：正体を隠したまま王位継承の駆け引きが行われる「仮面領」の一夜限りの舞踏会
- 手札＝「今夜だけ被っている仮面」というメタファー
- 脱落＝「正体を見破られ、舞踏会から退場させられる」

## GitHub Pagesへのデプロイ手順（未設定の場合）

すでにGitHub Pagesを設定済みであれば読み飛ばしてください。まだの場合の最短手順です。

1. GitHubにこのフォルダ一式（`index.html` / `mask-game.js` / `manifest.json` / `sw.js` / アイコン3種）をpush
2. リポジトリの Settings → Pages を開く
3. Source を「Deploy from a branch」、Branch を `main`（またはpush先のブランチ）／ `/ (root)` に設定して保存
4. 数十秒〜1分待つと `https://ユーザー名.github.io/リポジトリ名/` で公開される
5. スマホでそのURLをブラウザで開き、共有メニューなどから「ホーム画面に追加」

以降は本文書冒頭の「更新すると自動でスマホのアプリは更新されますか？」の流れで、pushするたびに中身が更新されていきます。

## GitHubを更新すると、スマホのアプリは自動で更新されますか？

**要点だけ先に：** 「削除・入れ直し不要で中身だけ更新される」という動きは実現していますが、**アプリを開き直すことが更新のトリガー**になります。ネイティブアプリのように閉じたままバックグラウンドで自動更新されるわけではありません（これはPWA全般の仕組み上の制約で、MASCARADE固有の制限ではありません）。

具体的な流れ：

1. GitHubにpush → GitHub Pages等のホスティングがビルド・デプロイ（数十秒〜1分程度）
2. スマホでMASCARADEのアイコンをタップしてアプリを開く
3. `mask-game.js` に登録された Service Worker が起動時に **最新の `index.html` / `mask-game.js` をまずネットワークから取りに行く**（今回、HTML/JSは「ネットワーク優先」方式に変更しました）
4. 取得できれば即座に最新版で表示。取得できなければ（オフライン時など）直近にキャッシュした版を表示
5. すでにアプリを開いたまま裏で待機していた場合は、新しいバージョンを検知した時点で**そのタブが自動的に1回だけリロード**され、最新化されます

ホーム画面のアイコン・インストール状態はそのままで、中身だけが更新されます。削除や再インストールは不要です。

**注意点**
- 更新が反映されるのは「オンライン状態でアプリを開いたとき」です。オフラインのまま開いた場合は直近のキャッシュ版が表示されます。
- GitHub Pages（またはそれに類する静的ホスティング）でHTTPS配信されていることが前提です。`file://` で直接開いている場合はService Worker自体が動作しないため、この自動更新の仕組みは働きません。
- ファイルを更新するたびに `sw.js` 内の `CACHE_NAME`（現在 `mascarade-cache-v2`）は必ず1つ上げる運用にしてください（同じ名前のままだと、静的資産側のキャッシュが更新されないことがあります）。

## 今回の更新内容（v39）― PC版：場の文言表示とカード表示の重なりを修正

### 原因

PC向けの画面幅（`min-width:700px`）ではカードが少し大きく表示される一方、ブラウザウィンドウの「縦の高さ」はスマホほど余裕がないことが多く（横長のウィンドウになりがちなため）、「場」の確認テキストを表示する枠に十分な高さの余白がありませんでした。加えて、ネストしたflexboxの一部要素に `min-height:0` の指定が抜けていたため、内容が収まりきらない時にスクロールではなく、下の「あなた」の手札エリアへ視覚的にはみ出して重なってしまう、という構造的な不具合がありました。

実際に1280×720（横長のノートPC相当）のウィンドウでこの重なりを再現できたため、修正後に同じ条件で解消されたことを確認しています。

### 対応内容

- 「場」の枠に最小限の高さを確保しつつ、内容がそれでも収まらない場合は（隣の枠に重ならず）**その枠の中だけでスクロールする**ように変更しました。
- ボタン（「この仮面を場に出す」「やめる」等）が、他の要素に隠れて押せなくなっていないかをPlaywrightで実際にクリックさせて検証済みです（要素が他の要素に覆われていると自動テストのクリック自体が失敗する仕組みのため、見た目だけでなく実際の操作可能性を確認できています）。
- **スマホ版（`min-width:700px`未満）のスタイルには一切手を加えていません**。実際に390×844のスマホサイズで表示に変化がないことも確認済みです。

### ついでに見つけた、別件の不具合について

修正の検証中、**1440px程度の広いPC画面幅では、逆にスプラッシュ画面の「MASQUERADE」ロゴが折り返してしまう**現象を偶然見つけました。今回の依頼内容（場とカードの重なり）とは別件のため、あえて修正はせず、こちらでご報告だけしておきます。対応をご希望でしたらお知らせください。

## 今回の更新内容（v36）

### 「部屋の作成がタイムアウトしました」の根本原因を特定・修正

接続テストが成功したにもかかわらず、実際の部屋作成だけが失敗するという情報から、原因を特定できました。

**原因**：Firestoreは「配列の中に、直接もう1つの配列を入れる」というデータ構造（array of arrays）を書き込めません。ところが、部屋作成時に送っていたゲームの状態データには、自分と相手それぞれの山札を`decks:[自分の山札の配列, 相手の山札の配列]`という、まさにこの禁止された形で保持している箇所がありました。接続テストは単純なテストデータだったため成功しましたが、実際のゲーム状態を送る段階で、この構造が壁になっていたと考えられます。

**対応**：ゲームの内部ロジックには一切手を加えず、Firestoreとやり取りする境界（送信時・受信時）だけに変換処理を追加しました。送信時は`decks`を`{d0:[...], d1:[...]}`というオブジェクト形式に変換し、受信時に元の配列形式へ戻します。実際にこの変換によって問題の構造が解消されることと、変換前後でデータの中身が完全に一致すること（JSONでのやり取りを模した往復も含めて）を自動テストで確認済みです。

### 「一夜を過ごしますか？」等の言い回しを変更

ご指摘の通り、「（相手）と一夜を過ごしますか？」といった言い回しは、対戦相手と夜を共に過ごすかのような、意図しない誤解を招きうる表現でした。同じ言い回しのパターンを使っていた以下4箇所をすべて変更しました。

| 箇所 | 変更前 | 変更後 |
|---|---|---|
| CPU対戦の説明文 | 仮面卿と、腕試しの一夜を。 | 仮面卿を相手に、腕試しの一局を。 |
| オンライン対戦の説明文 | 合言葉を交換して、誰かと一夜を。 | 合言葉を交換して、対戦相手を見つけよう。 |
| 対局開始の確認画面 | 「○○」との一夜が始まります。 | 「○○」との対局が始まります。 |
| 再戦の確認画面 | 同じ相手と、新たな一夜を過ごしますか？ | 同じ相手と、もう一度対局しますか？ |

なお、ゲームタイトルおよびサブタイトルに使われている「仮面領の一夜」「一夜限りの舞踏会」は、「（誰か）と一夜を過ごす」とは文法的に異なり、舞踏会という催し自体を指す表現（＝一晩限りのイベント、という世界観の説明）のため、そのまま残しています。もしこちらも変更をご希望でしたらお知らせください。

## 今回の更新内容（v31）

### 1. スプラッシュ画面「MASCARADE」ロゴが見えない不具合を修正

原因を特定しました。ロゴ文字は「グラデーション文字」という、文字の形に沿って背景のグラデーションを切り抜いて見せる技法（`background-clip: text`）で実装されていましたが、この技法は一部のAndroid端末のWebViewやアプリ内ブラウザ等で正しく描画されないことがあり、その場合は文字が完全に透明になって見えなくなってしまう、という不具合でした。

実際に自動テストでこの技法の挙動を詳しく調べたところ、条件によっては正常なはずの環境でも安定して描画されないことを確認したため、**この技法自体の使用をやめ**、単色の金色＋発光（text-shadow）による、どの環境でも確実に表示される方式に変更しました。同じ問題があったタイトル画面上部の「MASCARADE」ロゴ（対局画面でも常時表示されるもの）も、あわせて修正しています。

### 2. 背景を、よりゴージャスな配色に変更（プレビューあり）

白ベースの配色が簡素に感じられるとのことでしたので、アイコン・スプラッシュ画像の世界観（深い紫・黒・金）に合わせた、舞踏会らしい豪奢な配色「**Velvet Masquerade**」に変更しました。

- 背景：深い紫〜黒のグラデーション（アイコン画像の夜の雰囲気に合わせています）
- 差し色：金・紫（ワイン色）・青の3色を、ろうそくの灯りのような柔らかい光暈として配置
- 文字色：白に近いアイボリーで、暗い背景でもくっきり読めるように調整

実際の画面は、このチャット上の画像でご確認いただけます（スプラッシュ画面／タイトル画面／対局画面の3種）。もし色味や明るさの方向性を調整したい場合（例：もう少し明るく、もっと青みを強く、金色をもっと控えめに、等）は、お気軽にお申し付けください。

### オンライン対戦の設定方法（重要・作業が必要です）

オンライン対戦には、あなた自身のFirebaseプロジェクトが必要です。以下の手順で準備してください。

1. [Firebase コンソール](https://console.firebase.google.com/) で新しいプロジェクトを作成する
2. 左メニューの「Authentication」→「Sign-in method」から、**匿名（Anonymous）** を有効にする
3. 左メニューの「Firestore Database」から、データベースを作成する（本番モードでもテストモードでも構いません。セキュリティルールは手順5で設定します）
4. 「プロジェクトの設定」（歯車アイコン）→「全般」タブの一番下、「マイアプリ」で ウェブアプリを追加し、表示される `firebaseConfig` の値（apiKey、authDomain など）をコピーする
5. `mask-game.js` 内の `firebaseConfig`（ファイル冒頭から検索すると見つかります）を、コピーした値で書き換える：
   ```js
   const firebaseConfig = {
     apiKey: "...",
     authDomain: "...",
     projectId: "...",
     storageBucket: "...",
     messagingSenderId: "...",
     appId: "...",
   };
   ```
6. Firestore の「ルール」タブを開き、以下のセキュリティルールを貼り付けて公開する（**ランキング機能を追加したため、以前お伝えした内容から更新されています。再度貼り付け直してください**）：
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /rooms/{roomId} {
         allow read: if request.auth != null;
         allow create: if request.auth != null;
         allow update: if request.auth != null &&
           (resource.data.hostUid == request.auth.uid || resource.data.guestUid == request.auth.uid);
       }
       match /leaderboard/{uid} {
         allow read: if request.auth != null;
         allow write: if request.auth != null && request.auth.uid == uid;
       }
       match /_diagnostics/{docId} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
   - `rooms`：対局の部屋（これまで通り）
   - `leaderboard`：ランキング。全員が読めますが、自分の記録（自分のuidの文書）にしか書き込めません
   - `_diagnostics`：後述の「接続テスト」機能が一時的にデータを書き込んで読み書きを確認するための、テスト専用の置き場です

## アーキテクチャのポイント（Lis Noirの型を踏襲）

- `CARD_DEFS` にカード1枚＝1オブジェクトで定義。効果は `effect` 種別（`guessRank` / `peekRange` / `peekDeckBottom` / `protectSelf` / `peekDeckTop` / `doubleRedraw` / `secretRedraw` / `compareHand` / `foreseeTwo`）で分岐し、`Game.eff〇〇()` という汎用関数群で処理しています。
- ゲーム状態は `Game.state` に集約（`deck` / `players` / `turnIndex` / `phase` / `log` など）。
- 画面は `UI.render()` で対象エリアをまるごと再描画する方式（Lis Noirと同じ）。
- カードは画像全面表示＋レアリティ別の縁の輝き（CSSの `box-shadow`）で表現しています。画像そのものに額縁・数字・名前が描き込まれているため、テキストのオーバーレイは行っていません。

## テスト方法

`mask-game.js` には `window.__TEST_FORCE_CPU` フラグと `window.__masqueTestHooks`（`Game`/`CPU`/`UI`/`CARD_DEFS`を公開）を用意しています。jsdomから `window.__TEST_FORCE_CPU = true` を立てた状態で `Game.newGame()` を呼ぶと、両プレイヤーがCPUとして自動進行し、通常より短い待ち時間で最後まで自動再生します。本改修でも40戦連続の自動対戦を実施し、クラッシュなし・脱落決着／山札切れ決着／全員脱落による引き分けの3パターンすべてに到達することを確認済みです。
